# Image-to-Editable PPT Skills

将图片型 PPT、扫描页、PDF 页面或截图重建为可编辑的 PowerPoint（PPTX）。项目采用 **GPT 多模态识图 + 源图像素坐标 + 原生 PPT 对象 + 自适应视觉资产** 的混合路线，解决“整页图片看起来像 PPT，但文字、图标和布局无法编辑”的问题。

## 项目解决什么问题

很多 AI 生成的 PPT 实际上是一张或多张整页图片：视觉效果可以接受，但无法单独修改标题、正文、卡片、连线、图标和插图。本项目不把整页截图简单地铺回 PPT，而是分析页面结构并按对象类型重建：

- 文字、标题、段落和可识别的版式元素重建为原生可编辑文本；
- 卡片、色块、边框、规则、连接线、箭头和简单图形重建为 PPT 原生形状；
- 复杂插画、照片、发光效果和难以可靠矢量化的图标，使用源图裁剪、确定性处理或自适应图像生成；
- 每个对象保留源图像素坐标、处理方式、来源和验证结果，便于复核和继续迭代。

## 两种独立模式

| 模式 | 适用场景 | 核心策略 |
|---|---|---|
| [High Fidelity](./image-to-editable-ppt-high-fidelity.zip) | 视觉还原度优先，复杂图形较多 | 原生重建与高质量视觉资产并行，必要时生成或重生成，不设置固定的生图次数上限 |
| [Low Cost](./image-to-editable-ppt-low-cost.zip) | 希望减少不必要的生成调用 | 原生文字和几何优先，其次使用源图裁剪，只有复杂且影响较大的区域才调用图像生成 |

两个 ZIP 是完整、独立、可分别安装的技能包。一次任务只需要安装其中一个。

## 关键设计

### GPT 多模态识图，不依赖 OCR

页面文字、元素类型、层级关系、未知区域和源像素坐标由 GPT 多模态模型识别。默认流程使用 `--no-text-hints`，不调用 OCR 服务，也不把 OCR 作为隐式兜底。这样可以避免 OCR 文本框与视觉布局脱节，同时让模型直接理解卡片、插图、图标和组合关系。

### 固定坐标，减少布局失控

所有页面对象先在源图像素坐标系中定位，再映射到 PPT 页面坐标。文本框、形状和图像资产使用明确的左上角、宽度、高度、裁剪和层级信息，避免仅依赖“自动排版”导致位置漂移。

### 页面和资产并发

- 多页文件：页面识别、资产裁剪、图像生成、构建和渲染可以按依赖关系并发；
- 单页文件：使用页面内部的资产级并发，同时处理多个独立图标、插图和裁剪任务；
- `--max-concurrent-pages` 控制页面 worker，不是 ImageGen 次数上限；
- 每次运行记录实际识别调用、实际生图尝试、重试、失败、输出和耗时。

## 模型要求

### 共同要求

1. 支持图片输入的多模态模型，能够读取中文并输出结构化结果；
2. 能够定位对象的源图像素坐标，区分文本、原生几何、图标、插画和未知区域；
3. 具备图像生成或编辑后端，用于复杂视觉资产；
4. 具备确定性的 PPTX 构建器和 PowerPoint 兼容渲染器。

### 当前推荐配置

- 高还原度分析：GPT-5.6 Sol 或当前可用的最强 GPT 多模态推理模型；
- 低成本分析：GPT-5.6 Luna，页面密集或不确定时切换 GPT-5.6 Terra 或更强模型；
- 视觉资产：GPT-Image-2.5 Sunburst 或当前可用的高质量图像生成/编辑模型；
- PPTX 构建与验证：技能包内置的 `editppt`/Open XML 工作流和 PowerPoint 兼容渲染器。

模型名称是当前推荐，不是硬编码依赖。外部模型也可以使用，但必须满足相同的多模态分析、结构化输出、图像资产和 PPTX 构建能力要求。

## 可编辑边界

本项目的目标是“尽可能对象级可编辑”，不是无条件承诺每个像素都能变成矢量。文字、版式和简单几何通常可以编辑；复杂插画、照片、特殊发光效果和无法可靠分离的图形可能仍保留为独立图片对象。最终报告必须明确哪些区域是原生对象、哪些区域是图片层，不能把图片层描述为完全可编辑。

## 安装与使用

下载对应 ZIP 后，解压到：

`%USERPROFILE%\\.codex\\skills\\`

解压后的目录名应与技能名一致：

- `image-to-editable-ppt-high-fidelity`
- `image-to-editable-ppt-low-cost`

安装后，技能会根据输入的 PPT/PPTX/PDF/图片执行识别、重建、并发处理和渲染验证。输出应包含 PPTX、预览图、验证报告、耗时/用量日志和资产来源记录。
